## 假设 (预注册, 不事后修改)

H3: 600s 单次运行的精英档案 (top-20 可行解) 含足够多样的路由子结构, 对其做精确
集合划分重排 (SP) 能把 pr15/pr16/pr20 的可行最优显著压低 (≥1.5pp)。
H3a (多样性前提): 档案各解共享大部分路由 (嵌套局部最优), 池去重后有效列数少 →
SP 增益小 → 结论: 单轨迹池多样性是瓶颈, 路线级重组必须与种群/多轨迹配套。

## 方法

1. **收集**: 每实例一次 600s s42 运行 (配置与 09-03/04 探针逐键一致), 导出档案
   全部可行解的完整路由: {实例, best_cost, solutions:[{cost, routes:[{depot,
   seq(客户序列), cost}...]}...]}, results/sp_pool_{inst}_s42.json。
   实例: pr15 (240 宽), pr16 (288 宽), pr20 (288 宽) + pr06 (288 窄, 对照 —
   窄窗 600s 已 +1.15%, SP 上界预期小, 检验收益是否紧车队特异)。
2. **池**: 全部档案解路由并集, 按 (depot, seq, cost) 去重; 统计池大小/去重率/
   解间 Jaccard 重叠 (多样性量化)。
3. **SP 模型** (scipy.optimize.milp, HiGHS; D:\mdvrp\.venv 已有 scipy, 无需
   OR-Tools): 二进制 x_j = 选列 j; 每客户覆盖恰一次 (等号 1); 每车场列数 ≤
   vehicles_available; 最小化 Σ cost_j x_j。TW 在列内已可行 → 模型无 TW 约束。
   超时上限 300s, 报告 MIP gap。
4. **Sanity** (内置): 只用 best 解的列做 SP → 结果必须 == best_cost (模型正确性);
   全池 SP 目标 ≤ best_cost 恒成立 (best 解本身是可行覆盖)。
5. **指标**: SP obj vs best_cost 的增益 pp; 池统计; 每实例求解时间/gap。

## 判定阈值

- **增益 ≥1.5pp** (pr15/16/20 各实例均或均值): 单轨迹池已够 → 主算法 =
  ALNS 长跑/多 seed 池 + 终局 SP (matheuristic), 数学味主线, 立即可报;
  再补多轨迹池增益曲线作为扩展。
- **0.3 ≤ 增益 < 1.5pp**: 重组有效但被单轨迹池多样性卡住 → 设计结论:
  SP 增益随池多样性增长 (量化: 增益 vs 池大小/解间重叠), 主算法 = 种群
  (多样性来源) + SP 教育/终局精化组合; 下一步做种群交叉或用多 seed 池
  验证增益-多样性曲线。
- **增益 < 0.3pp**: 单轨迹池无收益 → 要么池多样性彻底不足 (检查重叠率:
  >90% 则说明多样性假设 H3a 坐实, 结论同上), 要么列级重组本身无效
  (每列内部已是局部最优且组合空间无增益) → 关 SP, 走种群交叉主线再评。
