## 机制形态 (实现 3 轮迭代, 每轮有诊断支撑)

- **v1 (放任超载)**: repair 容量门全开 + 罚后接受, λ 固定 = mult×初始成本/总需求
  (pr20 ≈ 2.29/单位)。**失败模式: 超载不受控漂移** — 300/300 迭代超载, max_excess
  585, 周期播种修复 (单遍贪心 _enforce_capacity) 全败 → 档案空, 无可行输出。
  根因: 修复顺序依赖 + λ 太低时贪心把客户塞进最近路由 (超载惩罚 < 远端绕行成本);
  单遍贪心修复对深超载 (数百单位) 系统性失败。
- **v2 (罚入修复成本 + 快反馈)**: repair 插入成本 = 距离增量 + λ×超载量 (与接受
  同 λ); 轨迹超载 → λ×1.05/迭代, 可行 → ÷1.05 (HGS 式快反馈); 播种改硬语义
  多轮乱序重插 (_soft_repair_hard)。**改善: 147/300 迭代超载, 有可行输出** —
  但 soft best 4119 vs hard 3782 (+8.9%)。
- **参数扫描 (pr20 300iter s42, mult×seedLS)**: 种子 LS 精化 (修复解 RVND 抛光后
  入档/锚定) 是唯一有效杠杆 (4119→3893, +2.9% vs hard); λ 基数上调 (mult=3/10)
  全面更差。固化为引擎默认 (种子 LS + 步长 1.05)。

## 判定 (按预注册)

- **H2 否定**: 两个预算点 (300/2000 iter) × 6 参数组合全部 soft ≥ hard +2.5~9pp,
  无任何配置接近预注册阈值 (pr15/16/20 均值 gap 低于 hard ≥1.5pp 且 pr06 无差)。
  方向一致地负 → 不跑 24-run 全批 (把已证伪假设做得更贵违反预算纪律)。
- **机制诊断 (为何负)**: ① 超载迭代占比 25-50% — 每次超载迭代 LS 被跳过 (RVND
  只接受完全可行改进), 播种每 50-100 迭代才拉回一次 → 有效精化预算净损失;
  ② 深超载 (max 583) 表明"距离节省 > λ×超载"的穿越窗口过宽, 而 λ 快反馈的
  时间常数 (~ln100/ln1.05 ≈ 94 迭代到上限) 追不上漂移;
  ③ 修复后可行解 (播种/自然) 从未显著优于 hard 臂同期档案 → 穿越没有打开新的
  可行盆地, 只产生需偿还的罚金债务。**本质: 本引擎是"可行精英档案 + 单轨迹"
  结构, LS/档案/父代全部锚定可行域; 软容量只在 repair 瞬态存在, 收益无法沉淀。**

## 对主线的含义 (与探针 1 合并后定稿)

探针 1 (docs/connectivity-probe-verdict-20260904.md) 否证了容量锁死前提 (容量可行率
36-72%), 因此本机制的负面结果属"机制在无锁处制造罚金债务"。真正的平台机制 =
600s 解已是 TW 感知局部最优, 距离改进候选枯竭且全被 TW 时间涟漪阻断 → 解锁需要
**路线/子结构级重组** (种群交叉/列池+SP), 不是轨迹内软容量 — FIS 在文献里是
**种群**方法 (HGSADC/MDFIHA 均带罚函数种群), 单轨迹 ALNS 底座上硬移植不成立。
