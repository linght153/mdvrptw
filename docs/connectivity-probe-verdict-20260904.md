## 判定

- **H1 (容量锁死) 否证**: 最高负载实例 pr20 (94%) 的 relocate/swap 容量可行率
  仍达 36-49% (2-opt* 11-15%); 邻域图没有被容量断开。"高负载 → slack≈0 →
  跨路由算子全被拒"的机制假设错误 — slack 分散在各路由 (每路由平均 ~10 单位),
  小需求客户总能找到可插入路由。**探针 2 的 H2 前提不成立** — 软容量穿越没有
  可解锁的东西, 其负面结果 (soft ≥ hard +2.5~9pp) 与此一致: 机制在无锁处
  制造罚金债务。
- **新发现 (替换锁死叙事) — 600s 解是 TW 感知的局部最优, 改进全被 TW 时间涟漪
  阻断**: 距离改进候选已近枯竭 (relocate 改进率 0.55-2.6%, swap/2-opt* ≈0.02-
  0.16%), 且**全部距离改进候选都 TW 不可行 (0%)**, 宽窗实例 (pr15/pr20) 同样
  如此 — 交叉验证 (增量 vs 全量调度, 候选级判定 107/107 与 13/13 一致) 排除
  检查 bug。机制: 单客户移动使后续客户到达整体后移 (服务+行驶累计), 即使宽窗,
  长路由尾部客户时间窗仍被推爆; RVND 收敛后, 单/双客户邻域彻底失效。
- **平台的结构解释 (修正版)**: 剩余 gap (pr06 1.15% / pr15 3.8% / pr20 6.5%)
  来自需要"多客户协同 + 重定时"的组合级移动: destroy/repair 是唯一能做整段
  重排的算子, 但随机大破坏在高质量解附近命中更好盆地的概率随质量提高而骤降
  → ALNS 平台。这与文献 HGSADC/MDFIHA 靠路线级交叉+教育重组 (保留好子结构,
  而非全随机破坏) 的机制选择吻合。

## 对方向决策的含义

1. 轨迹内单客户/双客户邻域 + 软容量 = 死路 (两个探针闭合, 别再投)。
2. 解锁平台的机制必须是**路线/子结构级重组**: 种群交叉 (HGSADC 式路线继承)
   或 列池 + 精确重排 (SP), 二者保留好路由组合, 绕开"随机破坏-贪心修复"的
   命中率瓶颈; 其中 SP 有数学学院辨识度且 TW 列可行性天然在列内。
3. TW 时间涟漪阻断单移动 → 任何新邻域若含"移动后重定时吸收等待"的评估
   (等价于插入点后移吸收) 可能翻出被 TW 误杀的改进 — 可作为子机制探针, 但
   预期收益低于路线级重组 (涟漪只是把改进率从 0.5% 压到 0, 本体是候选枯竭)。
