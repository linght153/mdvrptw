## 1. 最重要的发现: 双目标遗留污染

pr 实例经 instance_from_parsed 构造时 emission_model 落默认值
(base_emission_rate=0.155, alpha=0.3, green 线双目标遗留), 而 engine 的
best 更新/accept/档案全部用 `cost + emission` 混合标量比较, BKS/gap 却按
纯距离计 → **搜索一直在错误目标上运行** (emission ≈ 0.155×(1+0.3×负载)
× 距离, 同距离不同负载分布会翻转排序)。

修复: instance_from_parsed 默认排放归零 (base_rate=0.0/alpha=0.0),
calculate_emission 短路, removal_cost_delta 删除代数上抵消的全解重算。

## 2. 单目标化暴露的两个下游 bug (连带修复)

a) **Pareto 档案坍缩**: emission 维恒 0 时 "被支配即拒" 拒掉所有更高 cost
   解 → 档案只剩全局最优单点 → 父代选择失去多样性 → 搜索崩
   (pr20 2000 iter gap 9.9% → 18.6% 实测)。修复: ParetoArchive 加
   single_objective 模式 = 精英池 (去重 + 满时按 cost 保 top-N)。
b) **初始解无门禁入档案**: 紧车宽窗 (pr11) 初始解经兜底链仍带 TW 违规
   (tw_exc=317), 旧 Pareto 模式靠支配掩盖。修复: 初始解 is_feasible 门禁。
   连带: test_vehicle_limit 的 tight_single 实例 (容量 100 vs 需求 16,
   总需求 400=4×100) **无整数可行解** (100 不可被 16 整除), 断言改为容忍
   空档案; fixture 改 function scope。

全重算 246 万次) / LS 32% / objectives 17%。

  property 调用 + 每次 any() 遍历)

## 8. 方向 A 长预算验证 (600s × {base, prune} × 3 seeds, 2026-09-03 夜)

假设: 未饱和预算下剪枝的 44% 时间节省应转化为质量差。数据:

| 实例 | BKS | base 600s | prune 600s | Δ | base iter | prune iter |
|------|-----|-----------|------------|-----|-----------|------------|
| pr05 | 2962.25 | 3056.94 (3.20%) | 3056.94 (3.20%) | 0.00 | 7247/5680/8267 | 7608/5680/8589 |
| pr06 | 3588.78 | 3623.22 (0.96%) | 3616.95 (0.79%) | -0.17pp | 3823/3398/3874 | 4151/3600/3983 |
| pr20 | 2983.78 | 3245.73 (8.78%) | 3260.73 (9.28%) | +0.50 | 7010/9183/8302 | 5967/7384/6722 |

结论:
1. **pr05 三 seed base/prune best 完全同值** (质量平台 ~3050-3065 在
   600s 内被两配置同时达到; prune 多跑的迭代 (+5%) 无法突破平台);
   pr06 2/3 seed prune 更好 (s43 -14.2 显著), 均值 -0.17pp — 弱正向;
   pr20 (宽窗) 微负 — 边界确认 (120s/600s 一致)。
2. **方向 A 的时间公平质量收益在全部观测预算 (120s/600s) 下不显著**:
   修复后引擎的迭代-质量曲线在预算内趋于平台, 剪枝的时间节省主要
   落在平台区。可支撑的收益表述 = 同迭代时间节省 (LS 密集段 44%,
   全 run 平均仅 5-7% — profile 20iter 前段高估全 run: 中后期 accept
   率低 → LS 只在 freq 5 触发 → 剪枝作用面缩小)。
3. pr06 600s prune 0.79% / pr05 3.20% / pr20 9.28% (prune 口径) —
   引擎长预算水平: 窄窗 288 客户 600s 逼近 BKS (0.14% seed)。
4. 方向 A 作为论文贡献的定位须诚实: 无损性 + 时间节省成立 (机制
   性), 时间公平质量改善微弱且依赖平台未饱和; "加速器"组件定位
   而非独立质量增益来源。
