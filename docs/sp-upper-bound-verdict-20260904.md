## 判定

- **H3 否定**: 单轨迹档案池上 SP 增益 ≤ 0.015pp, 远低于 1.5pp 阈值 → 独立的
  "ALNS 长跑 + 终局 SP" 主线关闭。
- **H3a 坐实 — 精英档案多样性坍缩 (本批机制发现)**: 480 条路由出现只去重出
  59-81 个不同列 (83-88% 重复); 档案 top-20 成本全部挤在 best 的 0.18-1.07%
  内。证据链: 单目标精英池按 cost 保 top-N (archive.py, 无多样性压力) → 父代
  选择 (crowding 按一维 cost 间距) 从成本集中池取样 → 父代 ≈ 同一路由骨架的
  微扰 → 后代 = 骨架微扰 → 档案自我同质化。SP 没有可重组的多样性, 不是 SP
  无效, 是**池里没有新结构**。
- **对方向决策的含义 (重要)**: 任何"种群交叉/SP 教育"主线的**前置机制 = 档案
  多样性管理**, 不是交叉算子本身。HGSADC 的 load-bearing 组件是 diversity
  contribution (fitness = cost + penalty + diversity 项), 不是 route-copy
  交叉 — 我们引擎的档案在种群语义下是坏的 (cost-only 精英池)。
- 下一步候选 (按证据): ① 多 seed 池 → SP 增益曲线 (量化增益-多样性弹性,
  一次 ~40min×2-3 seed, 回答"SP 作为教育算子值不值"); ② 档案多样性修复
  (diversity-aware 裁剪: 按结构距离保 diverse top-k) + 种群交叉最小 A/B —
  ② 是任何种群主线绕不开的第一步, 且修复本身可独立成机制探针。
