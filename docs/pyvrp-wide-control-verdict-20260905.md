## ⚠️ 结论 1: 平台不是实例族固有难度 — 是单轨迹 ALNS 的形态缺陷

现成 HGS 系 600s 破 pr15/pr20 的 13 年 BKS (含 2026 MDFIHA 新界), 我们
充分迭代 (6000 iter/600s) 停在 +6~11%。"结构生成稀缺" 叙事修正为:
**稀缺的是单轨迹形态的结构生成/转化能力; HGS 系 (种群+罚域双空间+教育)
没有此问题**。我们的对照差距 = 形态级 (6-11pp), 非参数级。

## ⚠️ 结论 2: pyvrp 可用作全形态对照 — 自复刻 HGSADC 无必要

对照基线免费在手 (官方实现, 论文引用正当)。若需与 MDFIHA 特有机制对比

## 口径与方法学坑 (本批新增, 防再犯)

1. **pyvrp int 求解 vs 项目 float 口径的 TW 语义冲突**: pyvrp 整数距离
   同时作距离与行驶时间; 转 float 重算后部分解 TW 违规 (整数化 ±0.5/弧在
   长路由累积)。pr16 三 seed 最优解 (int 2832-2834 < BKS) 全部 float 边界
   外, **单客户移动 (逐位置试插前 300 便宜位) 无法修复** — TW 涟漪的又一
   实证 (需协同级移动); _enforce_tw 整条拆路由重插给粗糙上界 (3079-3360)。
   → 对照一律 float 重算 + 违规披露; pr16 报 int 口径 + 修复上界双口径。
2. **pyvrp 600s 对运行环境敏感 (偶发整批漂移)**: 同 seed 同预算曾出现整批
   结果降级 (pr15 int 2406→2445 且 float 不可行); 60s×3 连跑逐位一致 →
   短预算确定, 长预算窗口存在环境干扰。对策: 跑批前查残留进程 + int 成本
   偏离参考 (>×1.005) 自动重跑; 正常参考 pr15 2406 / pr16 2834 / pr20 2963。
3. **脚本参数序纪律**: bash 循环展开 "pr15 42" + 补 600 → 参数错位 (budget/
   seed 互换) 致整批 42s×seed600 白跑 — 循环用 name:seed 显式对再传
   `probe $name 600 $seed`。

## 方向含义 (打平框架的现实校准)

用户框架: "打平 = 一套方法有效性的证据"。现实:
- 我们的方法离打平差 6-11pp (形态级) — 单靠现有 gated 机制库 (div/admit/
  cx/pdiv/soft/score) 全部已证无稳健收益 → 打平路径 = 形态跃迁 (种群 +
  罚域双空间 + 教育, 即 HGS 家族机制在我们引擎上的完整实现)。
- pyvrp 作为标尺: 每加一个形态组件 → 同预算对照 → 差距收敛曲线即论文
  "方法演进" 叙事; 若最终打平/接近 → "我们的轻量混合框架 vs 官方 HGS"
  成立; 若形态齐全仍差 → 差距定位到具体机制 (消融), 转为机制研究。
- pr16 提示: 对照需注意 float/int 口径一致性 (论文若报 pyvrp 需同口径,
  或注明 int 求解 + float 重算的披露)。
