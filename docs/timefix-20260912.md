# timefix: 时间预算双缺陷修复与重跑 (2026-09-12)

触发: durfix 全批完成后核查 "pr20 600s base>pcxge 异常是否 bug"。
排查结论: 非 seed 噪声, 是两个真实工程缺陷。本文档 = 审计 + 预注册记录
(修复范围、门控、重跑清单先于重跑结果冻结)。

## 发现 1: 预算锚点逃逸初始化 (系统性, 影响全部 48 组时间预算运行)

- 机制: 引擎时间检查锚在"主循环开始" (旧 start_time 在初始化解之后取值),
  初始化耗时不计入预算。
- 旧引擎 pcxge 初始化 ≈1.4s 无感; durfix 后种群初始化 (8 成员 × 构造期
  TW+时长检查/修复链) 变贵 — 探针实测 (mode=1): **pr15 ~24s / pr16 ~78s /
  pr20 ~103s**; base 仅 ~1.5-2.6s。
- 实测超时: pcxge600 实际执行 **622s(pr15) / 675~688s(pr16) / 692~698s(pr20)**,
  而 base600=601s、pyvrp=600.0s 严格合规 → 600s 面板 pcxge 侧获得
  +22~+97s 不公平算力 (方向利于 pcxge)。
- 修复: 预算锚 = run_started (run 入口), 时间检查改 perf_counter (两处:
  普通路径 + 种群路径)。迭代模式 (max_time=1e9) 检查不可达 →
  B1-B5/B6 校准结果天然免疫。
- 验证: 修复版 pr20 s3 600s 实测 **wall=601.0s** ✓ (与 base/pyvrp 同)。

## 发现 2: pr20 s3 池级空转 (确定性复现, 时间预算特有)

- 现象: 600s 型配置 (stagnation 300 → 成员刷新阈值 50) 下, 8 个初始成员
  全部不可行 + 档案空 → 成员刷新落 _build_pool_member 重建 (每次 ~13s
  且全败; 38 次) → 烧光预算, **零可行解 (cost=None)**, 302 迭代 ~2s/迭代。
- 复现: 洁净机器重跑终态一致 (283 iters; cx=0 / mref=38 等逐项同); 原跑
  时段 03:08 (机器全空) → 排除外部负载。同 seed 6000iter 模式健康
  (stagnation 6000 → 刷新阈值 200, 风暴不触发) → 病态由"低刷新阈值 ×
  预算压力"耦合产生。
- 全库扫描: 48 组时间预算运行 + 141 组迭代运行中仅此 1 例; 该失败曾以
  cost=None 静默混入均值 (n=9 降级) — 汇总脚本已加显式报警。
- 修复: **timefix 防饥饿引导** — 时间预算模式 + 档案空 + 池全不可行 +
  已耗 ≥30% 预算时, 对最优成员做重预算联合爬坡 (wb=1M / step_cap 20k /
  100 rounds; 实测该状态 2.3s 可救), 成功 → 可行替补换最劣成员 +
  播种档案 (档案非空后刷新走精英路径, 死锁解除); 上限 5 次 / 间隔
  100 迭代 (多次机会)。仅时间预算模式 (max_time < 1e8) 且非罚域/软约束
  → 迭代模式逐位不变。
- 修复版实证: pr20 s3 600s → **cost=3788.9, 档案 20/20, cx 恢复 (175 次)**,
  引导触发 1 次 (当次爬坡未成, 随后自愈; 上限/间隔机制保留多轮机会)。

## 中性性与影响面

- 迭代模式 (B1-B5、B6 校准): 两修复门控不可达 → 轨迹不变; 仅新增 2 个
  统计键 (timefix_bootstrap_attempts/success)。位中性验证: pr15 s42
  popcxge 6000iter 重跑比对 (results/timefix_neutral; 除新键外逐字段)。
- 需重跑 (48 组): pcxge600 × pr15/16/20 × {s1-10, s42-44} + base600 ×
  pr15/16/20 × s42-44; 见 scripts/durfix_timefix_rerun.sh; 旧文件先归档
  results/durfix/archive_pretimefix/ 供两版对照 (判定文档记录)。
- 不重跑: pyvrp 侧 (600.0s 严格合规); B6 {sec}s BASE 运行 (init ~2s,
  占比 ≤0.3%, 记录为已知微小偏差); 迭代模式全部。
- 汇总: scripts/aggregate_durfix.py 对 cost=None 运行显式报警 (禁静默 n 降级)。

## 教训 (沉淀)

- 时间预算实验的"预算"必须定义到进程级总墙钟 (含初始化), 否则任何一侧的
  初始化成本变化都会静默改变对照的算力配比。
- 机制上线后要检查"病态耦合": 低停滞阈值 × 昂贵的失败重试 = 预算黑洞。
  修复须窄门控 (模式+状态+时间), 保证已批结果逐位不动。
- 失败运行必须以显式字段暴露 (cost=None), 汇总层禁止静默丢弃。
