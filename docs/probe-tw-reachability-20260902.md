# P0 探针: 时间可达弧剪枝潜力 + TW 白试率测量 (2026-09-02)

探针脚本: experiments/probe_tw_candidates.py (插桩计数版, 行为与引擎逐行一致)

## 动机

MDVRPTW 算法研究候选方向 A: 时间可达弧图驱动的无损邻域剪枝。前提是
"TW 不可行移动浪费显著" —— 先测量再决定是否值得做成论文组件。

## 结构事实 (全 pr01-20 扫描)

- 客户对硬不可达弧 (e_i + s_i + t_ij > l_j, 等待不可救, 最优解也不可能用):
  **pr01-10 (窄窗) 37-40%; pr11-20 (宽窗) 4-9%**
- 客户-车场可达: 全部可达 (Cordeau 车场距 < 窗截止) → 分配层无 TW 硬裁剪
- pr 家族本质 = 窗主导 (pr01-10) vs 车队主导 (pr11-20, 负载率 78-94%) 两组对照

## 行为测量 (300 迭代, seed 42, 引擎原配置)

### pr01 (窄窗 48 客户, wall 6.1s, best 1143.88 可行)
| 位置 | 候选枚举 | 弧硬不可达 (无损可剪) | TW 白试 |
|---|---|---|---|
| repair | 155,318 | **70.0%** | 87.7% 位置被整路由 TW 拒 |
| LS relocate | 608,831 | **72.5%** | 成本改进候选 98.2% 被 TW 拒 |
| LS swap | 549,575 | **81.7%** | 99.3% 被 TW 拒 |
| LS 2-opt* | 407,318 | **63.1%** | 96.2% 被 TW 拒 |
| LS two_opt | 74,309 | 0% (路由内可行弧) | 97.0% 被拒 (传播违规) |

repair 中无损弧剪枝覆盖了全部 TW 白试的 79.8%。

### pr07 (窄窗 72 客户): 与 pr01 同构 (repair 70.8%, relocate 72.4%, swap 78.8%, 2-opt* 59.9%)

### pr11 (宽窗 48 客户, wall 3.2s): 弧剪枝潜力骤降
repair 8.9%, relocate 12.9%, swap 17.0%, 2-opt* 7.3% — 剪枝率 = 窗宽的确定函数,
但 TW 整路由白试仍高 (65-93%) — 宽窗+长路由 (12 客户/车) 的违规来自时间传播,
非单弧不可达。

## 结论

1. **无损弧剪枝空间真实且可预测**: 窄窗族 ~60-82% 的 LS 候选与 ~70% repair
   位置可被弧可达性无损剪除 (不丢任何可行解); 宽窗族仅 ~7-17%。剪枝率随窗宽
   单调变化 = 实例静态结构 → 确定性机制 (区别于 P4-P6 否定的运行时随机交叉)。
2. **TW 白试率普遍 96-99%**: 成本改进候选几乎全部死在 TW 检查 (整路由传播),
   引擎把大量算力花在注定不可行的移动上; 弧剪枝只覆盖其中 repair 的 ~80%,
   传播型违规 (two_opt 0% 弧剪) 需要增量时间传播检查。
3. **方向 A 成立性判定: 有条件成立** — 剪枝空间 (60-82%) 远大于 granular 类
   有损方法的典型收益, 且无损; 但净收益需实现后 profile (省枚举 vs 检查开销),
   two_opt/传播类违规需另行处理。建议: 若做, 论文组件 = 可达图预计算 + repair/
   LS 候选无损过滤 + 剪枝率-窗宽结构律 (pr 两族天然对照)。

## ⚠️ 副产品: pr11 车辆数违规 bug (已修复 + 回归测试)

探针发现 pr11 (每车场 1 辆上限) ALNS 最终解 depot3 2 条路由 (车辆数违规,
TW/容量/覆盖全合规, is_feasible=False)。原版求解器复现 → 三层根因:

1. repair._insert_cheapest_cost_tw 兜底: "所有车场车辆已满"时无条件就近车场
   append 新路由 → 超车辆上限 (注释原称"罕见, 允许", pr11 紧车场景高频触发);
2. engine 主循环非 LS 迭代只 _enforce_capacity, 车辆数违规不在该路径处理
   (只在 LS 后的 _enforce_feasibility) → 违规解漏进档案;
3. archive.add 无可行性门禁 → 违规解 (成本更低) 支配可行解, 档案被污染。

修复 (commit 待):
- repair.py: 兜底改为 _nearest_depot_with_capacity + 未满才开新车,
  全满 → _lightest_route_insert (不增车, 与 _enforce_capacity 兜底同款);
- engine.py 主循环: 非 LS 路径补 _enforce_vehicle_limit;
- engine.py archive.add 前加 is_feasible 门禁 (档案纯净性);
- 测试: tests/test_vehicle_limit_tw.py 2 用例 (兜底不增车单测 + pr11 端到端
  档案全可行, 修复前必失败)。
- pr11-20 全族为 1-2 辆/车场紧车实例, 此 bug 直接影响 pr11-20 全部实验。
