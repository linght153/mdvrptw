## 探针 1 — 邻域连通性统计 (纯分析)

- 输入: pr06/pr15/pr20 各 600s s42 高质量可行解 (dump routes JSON, 复用
  probe_pr20_depot_assignment.py 模式: scripts/probe_connectivity_dump.py)。
- 指标 (scripts/probe_connectivity_analyze.py):
  * slack 分布: 每路由 cap − load; slack=0 路由占比; 总 slack。
  * relocate 容量可行率 = Σ 客户×位置 (目标路由 load+d ≤ cap) / 全候选数;
  * swap 跨路由对容量可行率 (双向容量检查);
  * 2-opt* 尾交换容量可行率 (交换后双侧负载 ≤ cap);
  * 可行∩成本改进率: 容量可行候选中 arc-delta < −1e-9 占比 (relocate/swap,
    2-opt* 抽样);
  * 可行∩改进∩TW 可行率 (仅对改进候选做增量 TW 检查, relocate/swap 全量,
    2-opt* 抽样 ≤2000)。
- 判定: pr15/pr20 的 relocate+swap 容量可行率 < 5% 且 pr06 > 15% (或 2-opt* 类似
  对照差) → H1 成立。若各实例可行率都高但改进率低 → 锁死假设不成立, 探针 2 动机
  撤回 (局部最优假说)。

## 探针 2 — 软容量 A/B (引擎机制 + 固定迭代)

- 机制 (config 键, 默认全关 → 默认行为逐位不变, 111 PASS 回归):
  * `soft_capacity=True`: repair/插入容量门放宽 (仍只插 TW 可行位);
    repair 后不强制容量, 只保车辆数 + TW 硬约束;
    接受准则目标 = 距离 + λ×容量超载总量, λ = mult × 初始可行成本 / 总需求
    (mult=1.0; 单位超载的边际代价 ≈ 平均单位需求成本);
    档案仍只收可行解 (纯净性红线);
    LS 只精化可行解 (RVND 内部只接受完全可行改进, 超载解跳过免烧迭代);
    每 soft_repair_interval=100 迭代把当前解强制修复回可行并尝试入档 (周期播种);
    终局强制修复当前解入档。
  * TW 实例修复算子 = greedy_cost_tw 唯一 (standard_alns 装配不变)。
- 对照: 逐键一致, 仅 soft_capacity False/True 不同。两臂同用
  stagnation_limit = max_iterations (纯固定迭代语义, 停滞重启阈值对称)。
- 实例 × seed × 臂: {pr06, pr15, pr16, pr20} × {42,43,44} × {hard, soft},
  固定 6000 iter, 串行独立进程 (bash for 循环), 24 runs。
- 参照: pr06 3588.78 / pr15 2433.15 / pr16 2836.67 / pr20 2983.78
  (docs/mdvrptw-bks-2026.md 参照值)。
- 输出: results/infeasible_ab/{inst}_s{seed}_{arm}.json →
  experiments/analyze_infeasible_ab.py 汇总 (均值±std/min/gap/软统计:
  超载迭代占比/播种数/最大超载)。
- 判定:
  * 通过: soft 在 pr15/pr16/pr20 的均值 gap 低于 hard ≥ 1.5pp, 且 pr06 差 < 1pp
    (方向一致才可解释为容量机制, 排除全局随机收益)。
  * 部分通过 (pr20 改善但 pr15/16 不改善) → 机制受实例结构调制, 报告但不立项。
  * 不通过 (无实例达 1.5pp) → 软容量穿越在本引擎无增益 → H2 否定, 该方向关闭,
    转向路线级重组 (种群交叉/SP) 或结构定制算子时不再重复此机制。
- 附加诊断: soft 臂超载迭代占比 (若 ≈0 → 罚太贵/修复太勤, 穿越没发生, 结果无效
  需调参重跑; 若 >60% → 罚太松, 结果标注)。
