# 列池外探针预注册: 跨运行池 SP + 互补双亲交叉×教育 = A1+教育线判定 (2026-09-04)

衔接: H3 (单运行池 SP 增益 ≤0.015pp) → H5 cx 否定 (父代冲突诊断) → A3 否定
(保序段移动改进枯竭) → 推论: 剩余 gap 需"生成档案外新路由列"。本探针直接测
**教育/组合机制能否生成池外列**, 一次判掉 A1 (结构互补双亲交叉) + 教育线。

## 分层假设

- **L1 (池层)**: 跨 seed 运行 (s42+s43) 合并列池的 SP 增益 > 单运行池 (H3 的
  0.015%) — 测"多 seed 池是否本身就破 H3 上界" (B 档候选 5 的多 seed 池版)。
- **L2 (教育层)**: 结构互补双亲 (跨运行档案、解间最大路由距离对) × route_copy
  交叉 × RVND 深教育, 生成**合并池外新列**, 且新列加入后 SP 增益进一步 > L1。
- A1+教育线开放 ⟺ L1 或 L2 增益 ≥ 0.1pp (pr20 总成本 3178 → ≥3.2 单位,
  可上表量级); 弱信号 = 0.02-0.1pp; 关闭 = 均 ≤0.02pp (≈H3 噪声量级)。

## 方法

1. 档案: s42 = results/sp_pool_pr20_s42.json (20 解, 池 59 列, 已有);
   s43 = 新跑 600s (probe_sp_collect.py pr20 600 43, 加 seed argv)。
2. 列池: (depot, seq) 序列级去重 (与 H3 build_pool 同口径); 集合级 (depot,
   frozenset(客户)) 另报 — 序列同集合 = 池内结构重排, 不算新结构。
3. **L1**: solve_sp (probe_sp_solve.solve_sp 复用) × {s42 池, s42∪s43 池};
   增益 vs best_cost。
4. **L2**: 双亲对 = argmax 解间 Jaccard 距离 (路由集 (depot, frozenset) 键,
   1 − |∩|/|∪|) — 档案内 top 对 (阶段 2a) + 跨档案 top 对 (阶段 2b);
   每对 K=4 次交叉 (route_copy_crossover, inherit_prob 0.6, 不同 rng);
   后代缺客户兜底重插 (repair 至多 2 轮), 仍不可行 → 丢弃计数;
   教育 = rvnd_improve(max_iterations=30) 循环至收敛 (≤5 轮);
   收集教育后解路由列 → vs 合并池 的池外计数 + 教育前后 cost。
5. 若 L2 有池外列: 池∪池外列 重解 SP → 增益增量。
6. 输出: results/education_columns_pr20_analysis.json; 判定按上述阈值。

## 执行纪律

- 600s 收集串行后台 (pr20 s43 单进程); 探针纯分析+LS, 无随机性争议
  (rng 固定记录)。
- 判定文档如实报告: 若 L1 已 ≥0.1pp → 多 seed 池方向开放 (教育线次要);
  若 L2 无池外列 → route_copy 形态 (整路由继承+贪心重插) 生成不了新结构,
  A1+教育线关闭, 与 H3/A3 合流为 "结构生成缺失" 总判定。
