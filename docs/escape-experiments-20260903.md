# pr20 逃逸策略实验 — 2026-09-03

背景: pr20 (288 客户宽窗紧车族) 120s×3seeds 均值 12.4%, seed 方差
8.64/14.84/15.48%。迭代已翻倍 (~2000) 质量不动 → 假设瓶颈在
"劣质 basin 逃逸"。六个机制变体 × pr20 × 3 seeds × 120s 检验。

## 结论

1. **六个逃逸机制变体无一对 pr20 有系统性收益** (v1 均值略好 0.8pp 但
   是单 seed 位移: s43 大改善 vs s44 恶化; v3/v5/v6 更差)。在
   120s × 单次 run 框架内, restart/深破坏/SA 冷却/档案策略不是
   pr20 瓶颈的杠杆。
2. **v2/v4 与基线逐位相同 = 机制从未触发**, 暴露一个工程缺陷:
   停滞深破坏分支 (stagnation > limit//2 = 150) 是死代码 — 停滞恢复
   (recovery_threshold = limit//3 = 100) 先把 stagnation 清零, 深破坏
   阈值永远到不了。v5 (提前到 45) 使分支生效但结果更差 (深破坏
   干扰已收敛结构)。
3. **快冷却 (v3) 有害** — pr20 需要保持高温/持续扰动, 后期贪心化
   反而恶化 (12.12/14.34/14.59 全部劣于基线同 seed)。
4. **时间预算才是 pr20 的杠杆** (600s 补充实验):

   | seed | 120s | 600s | iter(600s) |
   |------|------|------|-----------|
   | s42 | 8.64% | **6.50%** (3177.72) | 5967 |
   | s43 | 14.84% | **9.70%** (3273.03) | 7384 |
   | s44 | 15.48% | **11.65%** (3331.43) | 6722 |
   | 均值 | 12.99% | **9.28%** | ~6700 |

   差 seed 在 600s (~7000 iter) 收敛到 10-12% — 120s (~2000 iter)
   对 pr20 的差 seed 预算不足, 方差是"预算内迭代不足"的统计表现,
   不是算法结构缺陷。时间-质量曲线未饱和 (s42 600s 仍 6.5%)。
   数据: results/baseline_pr_120s/pr20_s{seed}_600s.json

## 工程改动 (全部向后兼容, 默认行为逐位不变, 111 PASS)

- engine: `deep_destroy_max_ratio` (默认 0.6), `stagnation_deep_ratio`
  (默认 0.5 → 原写死 150 语义), `restart_clear_archive` (默认 False)
- acceptance: 显式 cooling_rate 不被自动校准覆盖 (`_explicit_cooling`)
- benchmark_pr_baseline: 非 120s 预算输出文件名带 {budget}s 后缀
  (防覆盖 120s 归档)

## 论文口径启示
