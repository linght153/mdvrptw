## 判定 1: A2 (多样性进 fitness) 关闭

- 任何 κ 未赢 div (pr15 = div, pr20/pr06 差 0.7-0.9pp) → H-A2 "连续权衡优于
  硬阈值" 否定; κ 不敏感 (pr15 三 κ 逐位同值, pr20 0.05=0.10) → 无调参空间。
- 档案多样性确实随 κ 单调升 (pr15 列 70→138, Jaccard 0.59→0.27) 但质量不变
  → **档案多样性对单轨迹质量无直接贡献** (与 H3 坍缩叙事张力: 坍缩是父代
  质量问题, 单轨迹 best 与档案内容解耦)。

## 判定 2 (重大方法学发现): div 的机制归因修正 — 收益载体 = 准入放宽, 
多样性裁剪在宽窗上是负贡献

- **pr15: div = a2(全κ) = admit 逐位同值 2580.0975** — 三种裁剪 (阈值/各种
  κ fitness/纯 cost-only) 全同 → 裁剪策略零效应, 收益全来自共享的准入放宽。
- **pr20: admit (3185.89) < div (3209.21) < a2 (3237)** — 放宽准入 + 不做任何
  多样性裁剪 比 div 好 0.73pp、比 a2 好 1.6pp → **多样性裁剪在 pr20 是负贡献**,
  κ 越大负越多 (a2_k0.10 3238 > a2_k0.02 3237)。
- **pr06 窄窗: 所有放宽准入的臂都比 base 差 (div +1.1, a2 +1.9, admit +2.0pp)**
  → 窄窗上"放宽准入→少重启"有害 (停滞重启在窄窗有益 — 平台实例上重启 =
  新轨迹采样)。

## 机制链 (混杂源定位)

engine 把 **archive.add 成败耦合进 stagnation_count** (added → 0; 拒收 → +1),
停滞阈值 = max(30, stagnation_limit//3)。base 满档后大量拒收 → stagnation
累积 → 重启 (build_initial_solution 重爬坡) → **重启浪费迭代**。放宽准入 →
added 成功率高 → 少重启 → 轨迹连续 → 6000 iter 质量 +3.5pp (pr15/pr20)。
裁剪策略差异只通过混沌路径 (档案内容→1e-6 重复拒收→stagnation→重启时机)
影响轨迹 — 不稳定、不可归因。

## 对既有结论的修正 (重要)

- **population_ab 判定中 div "多样性裁剪部分支持 (−0.70pp)" 的机制归因作废**:
  div 臂 = 准入放宽 + 多样性裁剪 双变量混淆。正确解读: 收益 = 准入放宽
  (engine stagnation 缺陷的 workaround), 多样性裁剪无正贡献 (pr15 零, pr20 负)。
- 6000 iter 口径 (stagnation_limit=iters → 阈值 2000) 下 base 已少重启;
  **600s 口径 (stagnation_limit=300 → 阈值 100) 下 base 重启频繁 → 600s 平台
  数字本身含重启浪费** — 所有 600s 探针解 (connectivity/SP/教育列) 来自频繁
  重启引擎, "结构生成稀缺" 结论的底座需 600s admit 判别复验。
